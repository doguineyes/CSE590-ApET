## Define the contribution proxy before implementation

Start with a few equal-sized visual-token groups. Use the same image-derived
groups across that image's questions. Include low/middle/high reconstruction-error
regions and a seeded matched-size random control; log exact membership and group
sizes. Do not measure only retained tokens or only compression failures.

Proposed primary proxy: change in length-normalized, teacher-forced gold-answer
log-likelihood when a token group is perturbed. For a fixed canonical answer y:

    S(q) = mean over answer tokens of log P(y_t | image, question, y_<t)
    I(G, q) = S_unperturbed(q) - S_group-perturbed(q)

Positive I means the group's presence supports that particular answer under this
intervention; negative I means perturbing it increased answer support. Neither
sign alone establishes ground-truth visual relevance. Generated answer changes
and exact-match scores are secondary observations, not the only proxy.

An initial shape-preserving intervention can zero a small group of visual
representations while retaining sequence length, order and position IDs. Record
the exact representation stage and acknowledge that zero vectors are an artificial
perturbation. Use a sham/no-op control and repeated unperturbed measurements to
separate measurement noise from intervention effects. This is project-owned
instrumentation; native reference math remains unchanged.

Reconstruction errors must come from the native procedure at the stated stage.
The uncompressed native input path bypasses error calculation, so do not assume
the baseline already provides those errors. Pair observed native pre-compression
errors with the corresponding full-context token stream and record the mapping.
Compare errors within each stage; raw values at different feature spaces/layers
are not directly commensurate. Group interventions yield group contribution
proxies, not complete per-token importance rankings.

Use teacher forcing only to measure answer support; do not supply the gold answer
in a scored free-generation prompt. Fix answer spelling/casing before interventions.
Predefine how empty answers, multi-token targets and label ambiguity are handled.

## Run a small RQ1 pilot before expanding

1. Prepare/review the candidate collection; freeze IDs, controls and exclusions.
2. Screen the fixed TextVQA pool; record dataset-appropriate consensus scores and
   raw answers before finalizing its RQ1 membership.
3. Implement and verify the proxy on 3–5 questions from each of GQA, MMStar and
   TextVQA, at the input stage, with a few groups and no-op/reference repeats.
   Measure runtime, then expand to all three frozen subsets if practical.
4. Add a limited layer-16 analysis with controlled upstream context and explicit
   token mappings. The existing input-only/decoder-only baselines have different
   budgets and cannot by themselves isolate a layer effect.
5. Compare task/stage patterns across all three datasets, keeping the metadata
   and outcome-selected strata separate.

Inspect group error versus contribution within each question, disagreements
among questions about the same image, and task/stage differences. Keep images as
the grouping unit when describing uncertainty; do not treat correlated questions
or token groups as independent images.

TextVQA is designed for reading and reasoning about text in images; see its
[original paper](https://arxiv.org/abs/1904.08920). First screen model competence
on a fixed small sample. Baseline-correct cases are the denominator for
preservation; retain the screened sample and baseline-wrong cases separately
for context/gain analysis. Baseline-correct does not itself prove image grounding.
Use its dataset-appropriate scoring and raw image/question inputs rather than
silently reusing GQA exact matching or adding auxiliary OCR transcriptions.

For later RQ2, merging/drop/random controls need matched selection/budgets and
documented basis handling. A protected variant using gold-answer contribution
is an oracle diagnostic, not an ordinary inference method with unknown answers.
