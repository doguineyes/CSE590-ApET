## What must remain fixed in a merge comparison

Native input compression does more than keep a selected spatial subset. In
`llava/model/llava_arch.py`, it first computes E and the selected indices, then
places FPS source features into ten selected replacement slots, then merges
unselected sources into the other 278 selected targets before projection.

For a fair merge/no-merge pair preserve:

- Actual CLIP features, FPS source IDs, E and ranked/ordered selected indices.
- The exact **basis source-to-output-slot assignment**; the same unordered FPS
  or selected set is insufficient. Native boolean indexing assigns basis sources
  into spatially ordered slots.
- Output token count/order/positions, projector, prompt and generation settings.
- Native source eligibility and merge normalization for variants that merge.

In the no-merge arm, only the ordinary target averaging is omitted. Basis
replacement remains. Preserve the original seed rule; stochastic controls use
separate RNG streams so they do not change FPS draws or generation state.

Start input-only because changing input merging can change later decoder E and
selection. Combined input/decoder ablations would then change several factors.

source IDs are different objects. Reuse each realized random selected set for

## Proposal's merge-routing comparisons

With the native E-selected set and basis assignment fixed:

| Arm | Difference from native nearest-target merging | What it tests |
|---|---|---|
| No merge | Ordinary retained vectors left unchanged; unselected sources do not merge | Net merging effect for this fixed selection+basis |
| Native nearest | Original routing and averaging | Reference |
| Random destination | Randomize source-to-target routing independently of selection | Whether similarity-based routing matters |
| High-E protected | Keep a prespecified set of highest-E ordinary targets unchanged; route sources to nearest remaining eligible targets | Whether protecting highly distinctive retained states changes preservation |

For the random-destination primary control, prefer shuffling the realized native
destination list across unselected sources. This preserves each target's incoming
count and averaging denominator while disrupting similarity routing. Record
unchanged assignments as well; a random permutation need not change every source.
Uniform-independent destination sampling is a different control because it changes
the load distribution, and must be labeled separately if used. Use fixed seeds
and keep their RNG separate from native FPS.

For high-E protection, the new protocol freezes **28 of the 278 ordinary targets**,
with index tie-breaking. Native basis slots are already ineligible merge
destinations. Protecting targets requires rerouting their incoming sources, with
new counts recorded. A matched-size random-protected control is needed before
crediting E ranking specifically rather than merely protecting fewer targets.
Do not tune the protected count on the diagnostic rescues.

High E is distinct from high RQ1 I. The required protected arm follows the proposal's
E ranking. Gold-answer IH/zero-guided protection is optional and explicitly oracle;
it cannot be presented as a practical question-only rule. A high-I source absent
from the retained-target set cannot be protected just by excluding merge targets.
