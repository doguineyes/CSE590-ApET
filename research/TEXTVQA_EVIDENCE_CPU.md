# TextVQA CPU evidence audit v1

## Run

No Kaggle or Torch installation needed. Use the existing editor environment (NumPy,
Pillow and tqdm). The `.pt` loader only supports plain CPU tensor dictionaries with
an allowlist of rebuild/storage globals and bounds checks; it rejects other objects.
CLIP arrays must reproduce the original saved raw-byte fingerprint.

Official OCR file (Rosetta0.2 validation):
https://dl.fbaipublicfiles.com/textvqa/data/TextVQA_Rosetta_OCR_v0.2_val.json

Downloaded file is in `research/results/textvqa-ocr-source/`; URL and hash also travel

## Fixed definitions

- Match by exact image ID; normalized OCR text must equal a reference supported by
  at least3 of10 annotations. Use the native TextVQA answer normalizer. No fuzzy edits.
- Single OCR-word/box matches form **unique candidates**, not verified unique text
  occurrences. Repeated matches are ambiguous. Contiguous multiword OCR sequences
  are suggestions only because OCR order need not be reading order. Nonzero rotation
  or abs(yaw/roll)>10 degrees goes to geometry review. Unmatched is not zero evidence.
- Coordinates use native `expand2square`: integer-floor central offsets, original
  dimensions, then scale to336. The24×24 grid has14×14 pixels per patch. A patch is
  relevant if its area intersection with any matched box is strictly positive.
- Padding is a geometric patch-area fraction, not a pixel-intensity threshold.
- Detail is mean absolute horizontal plus vertical difference of saved normalized
  pixels, computed **within** each patch, without cross-patch boundary differences.
- Norm is the L2 norm of raw pre-merge CLIP features. E comes from original native
  diagnostics. Spearman uses average ranks for ties; constants yield undefined.
  Report all-patch, nonbasis and fully-nonpadding results separately.
- Native slot coverage is separate from direct-source coverage after basis overwrite.
  Basis sources follow the original input boolean-assignment ordering and decoder
  indexed-assignment ordering. Merge-source ancestry is traced separately across both
  stages. These paths are set membership, not amount or quality of preserved evidence.
- Layer16 positions refer to contextualized states. No claim that unretained original
  pixels are no longer represented, or that final coverage isolates stage2 causally.

## Analysis and audit

Keep all100 in performance/property reporting. Provisional coverage analysis uses
only unique candidates. For each question with varying full-credit outcomes, compare
mean coverage in correct vs wrong random seeds. Average these differences equally
across questions, with5,000 question/image bootstrap resamples (seed5901105). Also
report within-question score/coverage rank correlations and native direct-source
coverage minus random mean. Fixed20 seeds; no2,000-independent-example assumption.

Audit20 is chosen by a deterministic case-ID hash **among matched candidates**, without
outcome-based selection. `visual-audit20.json` generated by the script starts pending;
review notes live separately in the tracked audit file. Do not overwrite automatic
matches based on performance. Incomplete OCR and generic referents can confound even
unique matches. Sensitivity analyses must be labeled and preserve the primary tables.

This audit does not implement conditional-logit causal mediation, a new selector,
GQA replication, or new model inference. The first task is verifying measurement
quality and learning which competing hypotheses deserve controlled GPU tests.
